# Original v1.31 research-calculation callers: UI display versus normal recomputation

Original official local `ORION2.EXE` v1.31 SHA-256: `4e11be14217b4aafa1839f333bf5eba037f98b0c44e9e4752c96c464c260419f`. Complete machine-body hashes and exact checked instruction/call sites: `tools/audit_research_display_call_routes_v131.py`, `decompilation/reports/research_display_call_routes_v131_2026-10-16.json`. Source interpretation and limitations: `decompilation/annotated/research_display_call_routes_v131.md`.

The original linker callgraph identifies two direct callers of `Colony_Research_Production_`. Turn recalculation through `Pre_Import_Computing_` passes a **null** output pointer, confirmed by CODE `0xD1DFD XOR EDX,EDX; 0xD1DFF CALL 0xCFF74`. The on-screen pathway `Evaluate_Screen_Input_ -> Show_Research_Production_ -> Colony_Research_Production_` passes a **non-null** local stack output pointer, confirmed by source CALL at `0xB00B0` and `0xD03D6 LEA EDX,[EBP-0xBB8]; 0xD03DC CALL 0xCFF74`. The research calculator passes this distinction through to `Colony_Job_Production_` at `0xCFFE8`.

Significantly, regardless of that optional buffer choice on the normal path, the original `Colony_Research_Production_` writes **WORD colony +0xEB** at CODE `0xD0050` *before* deciding whether to format a report. The UI action therefore invokes a routine with a numeric state write, rather than only reading precomputed colony state.

An independently traced research nested-calculation branch (planet BYTE `+0x0F == 10/11`) may make a +2/+5 breakdown field available as an extra numeric worker component only in the non-null route. Controlled hypothetical fixtures derived from original code yield research output 0 for the no-report path and 1 for the report path under one set of tightly specified synthetic conditions. This is **not yet evidence the exact combined state is reachable in a genuine v1.31 savegame**, nor a DOS runtime differential result. It must not be labeled an established defect or silently corrected in the native remaster.

Eight complete original named function bodies were SHA-authenticated; 822 machine instructions were fully decoded **in seven bodies plus the specific UI call-site block**, with 55 exact opcode checks, six named call edges and thirteen controlled checks. The remainder of `Evaluate_Screen_Input_` is full-body hash verified but deliberately not instruction-coverage-claimed because its generic linear disassembly has ambiguous bytes outside the audited call-site span.

Follow-on proof obligations are to establish genuine original save-state reachability for the combined flags and planet code, compare original DOS numeric production before and after the UI action under that valid state, and explicitly decide whether preserving or fixing any observed discrepancy accords with `PROJECT_RULES.md`. This analysis changes neither gameplay nor the older unrecalculated 87% whole-executable estimate; game assets and executable were not committed.
