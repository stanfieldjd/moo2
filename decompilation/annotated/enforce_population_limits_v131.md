# MOO2 v1.31 — population-limit enforcement source reconstruction

**Status:** The original 489-byte named Watcom `Enforce_Population_Limits_At_Colony_` routine at CODE `0xDC97C` is reconstructed as bounded source-derived C. Its original 81-byte `Colony_Race_Pop_Limit_` wrapper, 128-byte seeded `Random_`, 70-byte `Shuffle_Int_`, and already-recovered 136-byte `Colony_Food2_Per_Farmer_` have been integrated. ## Recovered 489-byte algorithm

The original colony is **361 bytes** with population count BYTE `+0x0A` and four-byte population records at `+0x0C`. The population class is `record_dword & 15`. Original Watcom stack allocations provide a **42-byte marked-capacity array** and **ten signed-WORD cached class limits** (20 bytes). The derived host C rejects malformed counts over 42, classes above 9 and capacity indexes outside 0..41 instead of permitting out-of-bounds DOS memory accesses.

1. In reverse population order, original CODE `0xDC9C6` through `0xDCA09` counts class occurrences, calls `Colony_Race_Pop_Limit_` once for each encountered class, caches the capacity and marks the capacity index in the 42-byte array.
2. Source code calls `Shuffle_(population_pointer, count, stride=4)` at CODE `0xDCA16`. The original four-byte dispatcher uses `Shuffle_Int_`, now reconstructed with exact original `Random_` seed state.
3. For each **marked** threshold from **1 through 41** (original starts at 1, so a capacity-zero mark is not processed), the source reverse-scans the population and counts entries whose cached class capacity is at most that threshold.
4. If too many entries qualify, the function removes **one** in original priority order, overwriting that four-byte record with the last population DWORD and decrementing count. The scan **restarts at the same threshold**, recalculating candidate buckets until no excess remains.
5. Verified original removal-bucket order: class **9**, unclassified other-owner bucket, entry bits **4..6** equal the colony owner, class **8**, then class matching the colony owner's low-nibble value. Multiple entries in a bucket are visited in reverse and update the candidate pointer, making the earlier entry the chosen victim.
6. Finally the source calls the actual `Colony_Food2_Per_Farmer_` with the colony owner and a null contribution buffer. **When AX low WORD equals zero**, every remaining population record whose low WORD has neither bit `0x80` nor bit `0x100` and whose class is not 8 gets `word=(word & 0xFE7F)|0x80`. Otherwise source preserves those records.

For valid original game state, the host code reproduces this loop with typed size/climate capacity, seeded shuffle and food callbacks. It preserves source **non-transactional changes**: a failure after a preceding mutation is reported but does not roll back earlier writes. Host index, capacity and callback guards are deliberate differences from DOS on corrupt input.

## Full 81-byte race-capacity wrapper

`Colony_Race_Pop_Limit_` at CODE `0xD0C1D` calls the original `Size_And_Climate_Race_Pop_Limit_` with planet size BYTE `+0x05`, colony environmental BYTE `+0xE2`, and the selected race class. It sign-extends the low AX result with original `CWDE`. It adds **5** when player technology BYTE `+0x11A` is exactly 3 and **2** when colony building presence BYTE `+0x145` is nonzero.

Consequently removing **building ID 15** (which clears colony `+0x145`) changes population capacity **before** limit enforcement. This is covered in the integrated building-removal test; the size-and-climate formula itself remains a separately named unresolved callee.

## Exact seeded shuffle and RNG

Original `Random_(n)`:

- Reads/writes original global `_random_seed` (32-bit).
- Computes `q=UINT32_MAX/n`, `cutoff=q*n`.
- Repeats `seed=seed*0x41C64E6D+0x3039` modulo 2^32 while `seed >= cutoff` (original rejection sampling).
- Returns `seed/q+1`, in 1..n.

Original `Shuffle_Int_` iterates `i=0..count-1`, computes `j=i+Random_(count-i)-1`, and swaps complete four-byte population entries at i and j. The `Shuffle_` wrapper calls this helper for input stride 4; no synthetic shuffle is needed in the composed building/population test.

The derived C rejects RNG input n=0 (the DOS original executes unsigned `DIV` before its check), validates host pointers and uses a maximum RNG retry count for malformed/adversarial states. These are not claimed to be original DOS behavior.
